# 01_语言规范校对 · 技术架构设计

> 波次 2 交付物（2026-08-23）· 依据：基线能力清单（L-01~L-12）+ 顶尖标准对标表（P-01~P-08）
> 正式项目根目录：`14.1_paeg-lang-style-plugin\`（本设计为波次 3 开发蓝图）

## 1. 总体架构（四层 + MCP 标准件）

```
┌─────────────────────────────────────────────────────────┐
│ L1 接口层（API）                                          │
│  Flask API（校对/报告/配置端点）+ Web 静态页               │
├─────────────────────────────────────────────────────────┤
│ L2 服务层（编排）                                          │
│  ProofreadService：三级流水线编排 + 文体预设选择 + 报告聚合  │
├─────────────────────────────────────────────────────────┤
│ L3 内核层（能力）                                          │
│  BasicRules（基础级）│ SyntaxRules（语法级）│ Semantics（语义级）│
│  TermGuard（术语保护）│ TraceBuilder（修订痕迹）            │
├─────────────────────────────────────────────────────────┤
│ L4 基础层（复用基线）                                       │
│  LanguageRefiner（L-03/04/05/06）│ AI_TELLS（L-01）       │
│  AITasteDetector（L-02）│ weil_corpus（L-09）             │
│  forbidden_words（L-10）│ polish/lang_gate（L-07/08）     │
├─────────────────────────────────────────────────────────┤
│ MCP Server（fastmcp stdio）                               │
│  Tools: proofread/check_basic/check_grammar/check_semantic│
│  Resources: style_presets:// term_whitelist:// reports:// │
│  Prompts: proofread_workflow / domain_adapt / report      │
└─────────────────────────────────────────────────────────┘
```

**设计原则**：基线 L-01~L-12 全部沉淀在 L4 基础层原样保留；新增能力（三级校对/文体/术语/痕迹/报告）在 L2/L3 层叠加；MCP 标准件独立于 API 层（同一内核双出口）。

## 3. 核心接口定义

```
POST /api/proofread            # 全流水线校对
  in:  {text, domain(学术|公文|简历|法律|通用), levels:[basic|grammar|semantic]}
  out: {text, trace:[{pos, original, revised, reason, type}], report:{stats, suggestions}, preserved: float}
POST /api/proofread/check      # 单级检查（basic|grammar|semantic）
GET  /api/style-presets        # 文体预设列表
GET  /api/term-whitelist       # 术语白名单（可配置）
POST /api/export               # 导出（md|html|docx）
```

**原意保持校验**：语义级改写后计算相似度（字符级编辑距离 + 关键名词保留率），<95% 时降级为"仅建议不自动替换"（P-05）。

## 4. MCP 插件结构（顶尖标准）

| 原语 | 名称 | 说明 |
|---|---|---|
| Tools | `proofread(text, domain, levels)` | 全流水线校对，返回结构化 trace+report |
| Tools | `proofread_check(text, level)` | 单级检查 |
| Tools | `proofread_export(report_id, fmt)` | 导出报告 |
| Resources | `style_presets://list` / `term_whitelist://{domain}` | 只读配置资源 |
| Resources | `reports://{id}` | 历史校对报告 |
| Prompts | `proofread_workflow` | 三级校对工作流模板 |
| Prompts | `domain_adapt` | 文体适配模板 |
| Prompts | `report` | 报告生成模板 |

**契约**：命名全小写下划线；参数 JSON Schema 强类型；错误返回统一 `{error:{code,message}}`；无状态（会话由 Host 管理）。

## 5. 数据模型

```
ProofreadResult {
  id, ts, domain, levels[], source_text,
  trace: [{pos, original, revised, reason, type}],   # type: typo|punct|format|collocation|syntax|order|ellipsis|logic|ambiguity|wording
  report: {by_type: {type: count}, suggestions: [], preserved_score}
}
StylePreset { domain, term_whitelist[], rules_override{} }
```

## 8. Oracle 论证修订落实（2026-08-23 · 依据 08_Oracle论证记录 2.1 五条）

### 8.1 P-08 性能差距落点（Oracle 2.1-1）
- **L1 接口层补充**：异步任务队列 + 结果缓存（`TaskQueue`：长任务（语法级/语义级 LLM 路径）提交后台，返回 `job_id`，前端轮询/SSE 取结果；基础级纯规则同步直出）
- **§6 部署形态补充**：LLM 路径异步执行（后台任务 + 轮询/SSE）；结果缓存 TTL 24h
- **§7 验收对照表新增**：

| 顶尖标准 | 架构落点 | 验收 |
|---|---|---|
| P-08 性能 | 异步队列 + 结果缓存 | 基础级 ≥1 万字/分钟；语法/语义级可配置异步 |

### 8.2 文体口径统一（Oracle 2.1-2）
- **统一口径**：验收基线 5 文体（学术/公文/简历/法律/通用）；第 6 文体（新闻或图书）为扩展目标（P-02 与对标表 §一 同步标注）
- 对标表 §一"≥6 文体"与 §三 P-02 同步加注："验收基线 5 文体，第 6 文体为扩展目标"

### 8.3 MCP 导出闭环（Oracle 2.1-3）
- `POST /api/proofread` 的 out 增加 `id`（对应 ProofreadResult.id）——MCP `proofread_export(report_id, fmt)` 闭环
- 统一错误码枚举：`{code: "PARAM_INVALID" | "RESOURCE_NOT_FOUND" | "LEVEL_UNSUPPORTED" | "INTERNAL", message}`

### 8.5 semantic 规则通道定义（Oracle 2.1-5）
- **规则通道构成**：复用 L-02 AITasteSignals + L-05 重复检测信号 + 新增规则包（逻辑矛盾连接词检测/概念混淆术语对/歧义指代检测）——纯确定性，先于 LLM 通道
- **L-03 防降级包装**：语法级 LLM 矫正引擎对 LanguageRefiner.refine 采用包装调用（输出层加 trace 记录），内核只读不改；禁止绕过内核另写改写逻辑
- **原意保持**：语义级改写后相似度 <95% 降级为"仅建议不自动替换"（沿用 §3 契约）
